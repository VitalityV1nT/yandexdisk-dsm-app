## РОЛЬ И ЗАДАЧА

Ты — senior product-дизайнер и фронтенд-инженер, отлично знающий **Synology DSM 7** (DiskStation Manager) и его **Synology UI Framework (SUI)**. Пакеты DSM строятся из набора SUI-компонентов (Vue-обёртки `v-app-window`, `v-button`, поля ввода, диалоги), а не из произвольного HTML, — это критично для реалистичности.

Спроектируй интерфейс DSM-пакета «Яндекс Диск» и выдай **два результата**:

- **A. Интерактивный HTML/CSS-прототип** — один самодостаточный файл `index.html` (встроенные CSS и минимум vanilla-JS, без сборки и внешних зависимостей; допускается один CDN-шрифт). Прототип визуально имитирует окно приложения **внутри DSM 7.3.2** (SUI-стиль), весь текст — **на русском**.
- **B. Спецификацию `spec.md`** для реализации в существующем Vue+SUI коде пакета (структура — в конце промта).

## ПРОДУКТ И ЦЕЛЬ

DSM-пакет (.spk) «Яндекс Диск» для Synology NAS синхронизирует выбранную **локальную папку** NAS с **Яндекс Диском** (движок — `rclone bisync`, двусторонняя синхронизация). Раньше первичная настройка делалась по SSH; **цель — полная настройка из UI без SSH**. Приложение открывается как окно внутри DSM (как Hyper Backup, «Панель управления» и пр.). Интерфейс — для администратора NAS.

## ВИЗУАЛЬНЫЙ ЭТАЛОН — Synology Hyper Backup (DSM 7), `design/example_1.png`

Повтори раскладку и визуальный язык эталона:

- **Sidebar.** Сверху, в светло-серой панели, ряд кнопок-иконок:
  - **синяя `+`** — «Добавить папку»;

  Под кнопками — вертикальный **список папок**: каждый элемент = иконка папки + имя (1–2 строки) + справа круглый **статус-бейдж**. Выбранный элемент подсвечен светло-голубым фоном с синей левой границей.
- **Detail.** Светло-серый фон, белые **карточки** со скруглением (~4–6px) и тонкой рамкой. Три секции:
  - **Верхняя карточка (шапка):** слева большая круглая **иконка статуса** (зелёная галочка в эталоне), справа крупный заголовок («Успешно»), под ним 1–2 строки мелким текстом (дата последнего/следующего запуска, даты — синей ссылкой). Ниже — **синяя основная кнопка** + ряд серых иконочных кнопок.
  - **Нижний ряд из двух карточек:** левая и правая, каждая — список пар «подпись: значение», внизу серая кнопка действия. (В эталоне: «Получатель — Активно» и «Настройки задач» с иконкой-замком.)

**Палитра (приблизительно — подгони под скриншот):** фон тела `#ECECEC–#F4F4F4`; карточки `#FFFFFF`, рамка `#E0E0E0` 1px, радиус 4–6px; основной синий ~`#1A6FD6`; текст `#333`, вторичный `#767676`, разделители `#E5E5E5`. **Статусы:** успех `#3DB84F` (зелёный ✓), ошибка `#E84C3D` (красный ✕), предупреждение `#F0A30A` (янтарный ⚠), в процессе `#2D8CF0` (синий, спиннер ⟳), не настроено `#9E9E9E` (серый). Шрифт — системный sans-serif (Roboto/Helvetica).

## АДАПТАЦИЯ ЭТАЛОНА ПОД «ЯНДЕКС ДИСК»

### Sidebar
- Кнопка **`+` «Добавить папку»** — открывает диалог добавления.
  **Правило v1:** в текущей версии поддерживается **только одна** папка. Если папка уже существует — кнопка `+` **неактивна** (disabled), с подсказкой-tooltip «В этой версии поддерживается одна папка».
- Кнопка **`📄` «Журнал rclone»** — открывает подробный лог последней синхронизации.
- **Список папок:** иконка + имя папки + статус-бейдж (✓/⚠/✕/⟳/серый).
  **Важно для дизайна:** покажи список с **несколькими** папками (например, 3 — с разными статусами), чтобы продемонстрировать целевую мультипапочную раскладку. В спецификации отдельно зафиксируй правило v1 (одна папка, `+` неактивна).

### Detail — верхняя карточка (шапка статуса)
- Круглая иконка статуса + заголовок: **«Успешно» / «Ошибка синхронизации» / «Предупреждение» / «Синхронизация…» / «Ожидает первой синхронизации»**.
- **«Последняя синхронизация: `<дата-время>`»** (формат `дд.мм.гггг - чч:мм:сс`).
- **«Следующая синхронизация: `<…>`»** — по расписанию (см. ниже).
- Основная синяя кнопка **«Синхронизировать сейчас»**.
- Ряд иконочных кнопок: **«История синхронизации»** (этой папки), **«Настройка»** (открыть диалог редактирования), **«Удалить»**.
- В состоянии **«Синхронизация…»**: спиннер, строка прогресса (например, «Отправлено 12 · Получено 3»), кнопка «Синхронизировать сейчас» неактивна (или заменена на «Остановить»).
- В состоянии **«Ошибка»**: красная иконка, краткий текст ошибки + ссылка **«Подробнее в журнале rclone»**, кнопка **«Повторить»**.

### Detail — нижняя левая карточка «Папка»
- **Локальная папка:** `<dir>` (абсолютный путь).
- **Владелец:** `<владелец локальной папки>`.
- **Удалённый ресурс:** `yandexdisk:/<подпапка>`.
- **Подключение к Яндекс Диску:** «Подключено ✓» / «Не подключено» (без показа токена).

### Detail — нижняя правая карточка «Настройки синхронизации»
- **Удалённый ресурс:** `yandexdisk:`
- **Чистка thumbs:** «Вкл.» / «Выкл.».
- **Расписание:** «По Планировщику задач DSM» (по умолчанию) **или** «Каждые N минут» (если задан интервал — см. Опция B).
- **Последний результат:** «Отправлено (NAS → Я.Диск): X · Получено (Я.Диск → NAS): Y · Изменено: Z · Удалено: W».
- Внизу серая кнопка **«Настройка задачи»** (открывает раздел расписания / диалог).

## ДИАЛОГ «ДОБАВИТЬ / РЕДАКТИРОВАТЬ ПАПКУ» (модальное окно SUI)

Модальное окно поверх основного. Поля:

1. **«Локальная папка»** (`dir`) — поле ввода пути + кнопка **«Обзор…»** (выбор папки в стиле DSM). Подсказка: «Абсолютный путь; папка должна быть доступна для записи пользователю `sc-yandexdisk`». Под полем — индикатор живой проверки: «Папка доступна для записи ✓ / ✗».
2. **«Удалённый ресурс»** (`remote`) — поле ввода, значение по умолчанию **`yandexdisk:`**. Подсказка: «Можно указать подпапку: `yandexdisk:/Backup`». (Имя remote `yandexdisk` фиксировано — в спецификации отметь, что меняется только подпапка.)
3. **«Чистка thumbs»** (`clean_thumbs`) — переключатель Вкл./Выкл. Подсказка: «Удалять файлы эскизов (`@eaDir`/thumbs) перед синхронизацией».
4. **«Подключение к Яндекс Диску»** (запись `rclone.conf`) — секция:
   - **Tier 1 (основной путь):** поле (textarea) **«JSON-токен»** + инструкция: «На компьютере с браузером выполните `rclone authorize "yandex"` и вставьте сюда строку вида `{...}`» + кнопка **«Подключить»**.
   - **Tier 2 (показать, но пометить):** кнопка **«Войти через Яндекс»** (вход через OAuth прямо из UI). В прототипе кнопка видима; в спецификации помечена как **вне MVP, требует одобрения** (встраивание `client_id`/`secret`, зависимость от стороннего OAuth-приложения).
   - В режиме редактирования при уже настроенном токене — индикатор **«Подключено ✓»** (значение токена не показывать никогда).
5. **«Расписание»** — выбор: «Вручную / по Планировщику задач DSM» (по умолчанию) **или** «Каждые `[N]` `[минут/часов]`». Поле интервала — **Опция B**: в прототипе показать; в спецификации пометить как **вне MVP, требует одобрения** (затрагивает инвариант «нет резидентного демона»).

Кнопки внизу диалога: **«Сохранить»** (синяя) и **«Отмена»**. Удаление папки — из шапки detail, не из диалога.

## ЭКРАНЫ И СОСТОЯНИЯ (показать все)

1. **Главный — «Успешно».** Sidebar со списком (несколько папок, верхняя выбрана и успешна) + detail в состоянии «Успешно».
2. **Состояния статуса.** То же окно, но detail в состояниях: **Ошибка**, **Предупреждение**, **Синхронизация… (прогресс)**. Удобно: в списке слева сразу разные бейджи.
3. **Первый запуск (пусто).** Список папок пуст; в основной области — пустое состояние: «Папок пока нет. Нажмите `+`, чтобы добавить первую папку синхронизации». Кнопка `+` активна и акцентирована.
4. **Диалог добавления/редактирования** (модальное окно поверх основного экрана).

**Реализация переключения в прототипе:** добавь небольшую **«панель прототипа»** (вне окна DSM, явно подписанную «Служебная панель прототипа — не часть продукта») с переключателями: статус (Успешно/Ошибка/Предупреждение/В процессе), «Открыть диалог», «Первый запуск (пусто)». Само окно DSM при этом должно выглядеть аутентично.

## ДАННЫЕ И КОНТРАКТЫ БЭКЕНДА (для точности дизайна и спецификации)

UI читает/пишет состояние через CGI и обёртку `yandex-disk`. **Реальные поля:**

- **`config.cfg`** (ключи): `dir` (абс. путь), `remote` (по умолч. `yandexdisk:`), `clean_thumbs` (`0|1`), `interval` (зарезервирован, Опция B). Старый файл без новых ключей обязан читаться.
- **`sync.state`** — 7 полей через `|`: `status|timestamp|result|sent|received|modified|deleted`.
  - `timestamp` — формат `дд.мм.гггг - чч:мм:сс`;
  - `sent` — NAS → Я.Диск (отправлено), `received` — Я.Диск → NAS (получено), `modified` — изменено, `deleted` — удалено;
  - старый 3-полевой формат (`status|timestamp|result`) должен оставаться читаемым.
- **Имя remote `yandexdisk`** фиксировано (контракт). В `rclone.conf` — секция `[yandexdisk]`, права `0600`, владелец `sc-yandexdisk`.
- **Ключ вкладки = имя CGI.** Существующие: `status` / `log` / `sync_log`. Новая вкладка/эндпоинт настроек: **`settings`** → `settings.cgi`.
- **Подкоманды обёртки** (источник данных для UI): `get-config` (вернёт `dir`/`remote`/`clean_thumbs`/`interval` + **флаг** «токен настроен», без значения токена), `set-folder`, `set-token` (JSON со stdin), `check-folder` (существует/доступна/владелец).

**Маппинг статуса → визуал:** значения `status`/`result` из `sync.state` отображать как Успешно/Предупреждение/Ошибка/В процессе/Не настроено (точные строки бэкенда уточняются при реализации).

## ЖЁСТКИЕ ОГРАНИЧЕНИЯ (зафиксировать в спецификации, не нарушать в дизайне)

- **Только SUI-компоненты.** Каждый элемент должен иметь аналог в SUI/Vue (окно `v-app-window`, кнопки `v-button`, поля ввода, чекбокс/switch, модальный диалог, иконки статуса). Никакого «произвольного» веба, выбивающегося из DSM.
- **Одна папка в v1.** Мультипапочная раскладка — задел на будущее; в v1 `+` неактивна при наличии папки. Настоящая мультипапочность потребует переработки бэкенда (несколько `config`/remote/состояний/задач) — отметь объём в спецификации, **не** проектируй его реализацию здесь.
- **Безопасность токена.** OAuth-токен никогда не показывается в UI после сохранения, не попадает в логи/ответы; пишется атомарно в `rclone.conf` `0600`. (В дизайне: только индикатор «Подключено ✓», поле ввода — лишь при вводе/замене.)
- **Approval-gated (вне MVP).** Tier 2 («Войти через Яндекс») и Опция B (интервал в UI) показать в макете, но в спецификации явно пометить «требует одобрения человека», с причинами.
- **Локализация:** весь UI на русском. **Размер окна:** стартовый ~960×600, изменяемый, с разумным минимумом (исходный пакет — 800×500; новая раскладка просторнее). **Тема:** светлая (как эталон).

## ТРЕБОВАНИЯ К РЕЗУЛЬТАТУ

### A. `index.html` (прототип)
- Один самодостаточный файл; встроенные CSS и минимальный vanilla-JS (открытие диалога, переключение состояний). Без фреймворков/сборки.
- Аутентичное окно DSM (title bar + sidebar + detail), точные русские подписи (используй формулировки из этого промта).
- Все 4 экрана/состояния доступны через «служебную панель прототипа».
- Адаптивность не требуется (фиксированное окно), но раскладка не должна ломаться при ресайзе окна браузера.

### B. `spec.md` (спецификация) — разделы:
1. **Обзор** и соответствие визуальному эталону.
2. **Карта экранов и состояний** (с привязкой к скриншотам/секциям прототипа).
3. **Компонентная карта:** таблица «элемент UI → SUI/Vue-компонент → где в существующем коде (`spk/package/ui/main.js`, новая вкладка `settings`)».
4. **Поток данных и контракты:** какие CGI/подкоманды вызывает каждый экран; маппинг полей `config.cfg` и `sync.state` на элементы UI; формат и эндпоинт `settings.cgi`.
5. **Диалог добавления/редактирования:** поля, значения по умолчанию, правила валидации (абс. путь; `remote` `^[A-Za-z0-9_-]+:(/.*)?$`; `clean_thumbs` `0|1`; токен — JSON с `access_token`), тексты ошибок.
6. **Правило одной папки в v1** + что нужно для настоящей мультипапочности (оценка объёма, без реализации).
7. **Безопасность и канон-инварианты** + список **approval-gated** (Tier 2, Опция B) с причинами.
8. **Локализация, размеры окна, темизация.**
9. **Открытые вопросы и проверки только на NAS.**

Сначала кратко изложи план макета (1 абзац), затем выдай `index.html`, затем `spec.md`.
