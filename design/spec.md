# Спецификация UI пакета «Яндекс Диск» для Synology DSM 7.3.2

> Парный документ к прототипу `design/prototype/index.html` и брифу
> `design/ui-design-brief.md`. Описывает реализацию в существующем Vue+SUI коде
> пакета (`spk/package/ui/`) с сохранением контрактов канона (`CLAUDE.md`,
> `docs/ui-config-migration-plan.md`).
>
> Прототип — визуальный эталон раскладки и поведения. Эта спецификация —
> что и как переносить в код, какие контракты бэкенда задействованы и где
> проходят границы MVP / «остановись и спроси человека».

---

## 1. Обзор и соответствие визуальному эталону

Интерфейс повторяет раскладку Synology Hyper Backup (DSM 7, `design/example_1.png`):
**мастер-детейл** — слева боковая панель со списком папок и кнопками, справа —
подробности по выбранной папке в трёх секциях (шапка статуса + две карточки).

**Ключевое архитектурное решение (см. §6):** дизайн показывает *несколько* папок
(целевая раскладка), но **v1 реализует одну** папку: кнопка «+» неактивна, пока
существует хотя бы одна папка.

**Соотношение со старым UI.** Текущий `main.js` — это окно с тремя вкладками
(`status` / `log` / `sync_log`). Новый дизайн заменяет вкладочное окно на
**дашборд**: «История» и «Журнал rclone» становятся кнопками-модалками, а не
вкладками. **Контракт «ключ вкладки = имя CGI» сохраняется на уровне данных** —
дашборд по-прежнему обращается к тем же CGI как к эндпоинтам данных (см. §4),
плюс добавляется новый `settings.cgi`.

**Соответствие статуса визуалу** (значения из `sync.state`, поля `status`/`result`):

| Визуальное состояние | Иконка/цвет | Источник |
|---|---|---|
| Успешно | зелёная ✓ `#43b14b` | `status`=ok, `result`=success |
| Предупреждение | янтарная ⚠ `#f0a020` | `result` указывает на частичный успех / пропуски |

> состояний держать **в одном месте** (JS-словарь в `main.js`).

## 4. Поток данных и контракты бэкенда

UI — тонкий клиент. Вся запись/чтение конфигов делегируется обёртке `yandex-disk`
(канон: общая логика — только в `common.sh`). Используемые эндпоинты и подкоманды:

| Действие UI | Эндпоинт / подкоманда | Метод | Примечание |
|---|---|---|---|
| Состояние выбранной папки | `status.cgi` → `yandex-disk status` | GET | уже есть |
| История состояний | `log.cgi` (`status_history.log`) | GET | уже есть; модалка «История» |
| Журнал rclone | `sync_log.cgi` (`rclone.log`) | GET | уже есть; модалка «Журнал rclone» |
| Очистка истории | `clear_log.cgi` | POST | уже есть |
| Преднаполнение формы | `settings.cgi` → `yandex-disk get-config` | GET | **новое** |
| Сохранить папку | `settings.cgi` → `yandex-disk set-folder <dir> [remote] [clean_thumbs]` | POST | **новое** |
| Сохранить токен | `settings.cgi` → `yandex-disk set-token` (JSON со stdin) | POST | **новое** |
| Проверка папки | `settings.cgi` → `yandex-disk check-folder <dir>` | GET | **новое**; индикатор в форме |
| Синхронизировать сейчас | `settings.cgi` → `yandex-disk sync` | POST | оборачивает существующий sync |

**Контракт `settings.cgi`** (новая вкладка/эндпоинт `settings` = имя CGI):
- `GET` → JSON состояния формы: `dir`, `remote`, `clean_thumbs`, `interval` (если
  есть) и **флаг** `token_configured` (булев). **Значение токена не отдаётся
  никогда** (`is_token_configured()` в `common.sh` уже даёт флаг по наличию секции
  `[yandexdisk]`).
- `POST` → парсит поля, вызывает соответствующую подкоманду, возвращает
  результат/ошибку. **Доступ:** только из аутентифицированной админ-сессии DSM;
  для мутаций проверять `SynoToken` (CSRF) — критично, т. к. CGI исполняется
  как root (Phase 0).

**Поля данных (источники истины):**
- `config.cfg`: `dir`, `remote` (по умолч. `yandexdisk:`), `clean_thumbs` (`0|1`),
  `interval` (зарезервирован под Опцию B). Старый файл без новых ключей обязан
  читаться (`cfg()` возвращает пустую строку для отсутствующего ключа).
- `sync.state` — 7 полей `status|timestamp|result|sent|received|modified|deleted`;
  старый 3-полевой формат остаётся читаемым (`sync_state_line()`).
- `timestamp` — формат `дд.мм.гггг - чч:мм:сс` (`_now()` в `common.sh`).
- Направления: `sent` — NAS → Я.Диск (отправлено), `received` — Я.Диск → NAS
  (получено), `modified` — изменено, `deleted` — удалено.

**Уже реализовано в `common.sh`** (Phase 1) и переиспользуется формой:
`validate_dir`, `validate_remote`, `validate_token`, `is_token_configured`,
`write_cfg_atomic`. Форма UI должна отражать те же правила (§5), но **источник
истины валидации — обёртка**, а не JS.

## 5. Форма «Добавить / Редактировать папку»

Поля, значения и привязка к валидаторам обёртки:

| Поле | Ключ | Тип | По умолчанию | Валидация (обёртка) |
|---|---|---|---|---|
| Локальная папка | `dir` | текст + «Обзор…» | — | `validate_dir`: абсолютный путь `^/…`; без перевода строки; без `"`; без подстроки ` #`. Существование/права — `check-folder` |
| Удалённый ресурс | `remote` | текст | `yandexdisk:` | `validate_remote`: `^[A-Za-z0-9_-]+:(/.*)?$`. Имя `yandexdisk` фиксировано — редактируется только подпапка |
| Чистка thumbs | `clean_thumbs` | switch | Выкл. (`0`) | только `0`/`1` |
| OAuth-токен | `rclone.conf` | textarea | — | `validate_token`: JSON в `{ … }` с непустым `access_token` |

**Поведение формы:**
- **Живая проверка папки.** По `blur`/изменению `dir` вызывать `check-folder`,
  показывать: «✓ доступна для записи sc-yandexdisk» / «✗ нет прав → подсказка про
  права общей папки в Панели управления DSM» / «папка будет создана».
- **Токен — только при вводе/замене.** В режиме редактирования при
  `token_configured=true` показывать «Подключено ✓» и ссылку «Заменить токен»;
  поле ввода скрыто до явного действия. Значение токена в форму **не
  подгружается** и нигде не отображается.
- **Сообщения об ошибках** — рядом с полем, по коду ошибки от обёртки
  (невалидный путь / путь с ` #` / относительный путь / не-JSON / JSON без
  `access_token` / remote не по шаблону).
- **Кнопки:** «Сохранить» (основная) → `set-folder` (+ `set-token`, если токен
  введён); «Отмена» — закрыть без изменений. Удаление папки — из шапки детали.

## 6. Правило одной папки в v1 и задел на мультипапки

**v1 (реализуется сейчас):**
- Backend хранит **одну** конфигурацию: один `config.cfg`, один remote
  `yandexdisk`, один `sync.state`.
- Список в боковой панели показывает **0 или 1** элемент.
- Кнопка «+» **неактивна** (`disabled`), пока существует папка; tooltip:
  «В этой версии поддерживается одна папка».
- Мастер-детейл раскладка применяется и для одной папки (single-item list).

**Дизайн-задел (показан в прототипе несколькими папками):** раскладка готова к
списку из N папок без переверстки.

**Что потребуется для настоящей мультипапочности (вне текущего плана — отдельная
задача с одобрением):**
- несколько именованных конфигов (например, `config.d/<id>.cfg`) вместо одного
  `config.cfg`;
- несколько remote или несколько подпутей на одном remote (имя `yandexdisk`
  фиксировано — придётся вводить схему имён/подпапок);
- несколько `sync.state` и несколько `flock`-замков (по одному на папку);
- несколько задач Планировщика / расширение триггера;
- ревизия всех потребителей контрактов (`yandex-logger`, `start-stop-status`,
  тесты, golden).

Это **затрагивает контракты канона** и в спецификацию реализации v1 **не входит**.

## 7. Безопасность и инварианты канона

**Обязательные инварианты (не нарушать):**
- OAuth-токен **никогда** не в логе, stdout, истории, ответе CGI, git. В UI после
  сохранения — только флаг «Подключено ✓».
- Токен не передаётся через argv (`set-token` читает JSON со stdin).
- `rclone.conf` — `0600`, владелец `sc-yandexdisk`; запись атомарна
  (`write_cfg_atomic`, `umask 077`).
- CGI исполняется как **root** (Phase 0), но конфиги пишутся **со сбросом
  привилегий** до `sc-yandexdisk` (`sudo -u sc-yandexdisk yandex-disk
  set-folder|set-token`) — файлы сразу принадлежат `sc-yandexdisk`, без
  root-owned секретов.
- Мутации — только из аутентифицированной админ-сессии DSM; для POST проверять
  `SynoToken` (CSRF). Инъекция в root-CGI = компрометация root — валидация §5
  критична.
- `run-as: package` не повышать; `--exclude`-список `_bisync` не урезать.
- Новые файлы под воспроизводимость: `settings.cgi` → в `POSIX_SH` (`build.sh`) и
  `eol=lf` в `.gitattributes` (правки гейтов — **отдельным PR**).

**Функции в макете, помеченные «вне MVP» — требуют одобрения человека перед
реализацией:**

| Функция | Где в UI | Почему gated |
|---|---|---|
| **Tier 2 «Войти через Яндекс»** (in-UI OAuth) | секция «Подключение» в форме | встраивание `client_id`/`secret` в открытый пакет, зависимость от стороннего OAuth-приложения, обмен кода на токен сетевым запросом из CGI; NAS-валидация. Открытый вопрос плана §3.2/§11 |
| **Интервал расписания в UI** (Опция B) | секция «Расписание» в форме | ключ `interval` + триггер из `yandex-logger` размывает инвариант «нет резидентного демона»; нужно явное одобрение. План §3.3/§11 |

**MVP по умолчанию:** Tier 1 (вставка JSON-токена) + Опция A (ручная задача в
Планировщике задач DSM, с готовой к копированию командой). В прототипе обе
gated-функции **показаны** с плашкой «вне MVP», но в коде их включать только
после одобрения.

## 8. Локализация, размеры окна, темизация

- **Язык:** весь UI на русском (формулировки — из прототипа). Тексты держать в
  одном месте `main.js` для будущей локализации.
- **Размер окна:** текущий `v-app-window` — `800×500`. Новая раскладка
  просторнее: рекомендуется стартовый **~960×600**, `resizable=true`, разумный
  минимум (≈760×460), чтобы две нижние карточки не ломались. При узком окне нижний
  ряд карточек может переноситься в столбец (`flex-wrap`).
- **Тема:** светлая (как эталон DSM 7). Тёмная тема в этой задаче не требуется.
- **Шрифт/палитра:** системный sans-serif; палитра DSM (синий `#2d7fd9`, фон
  `#ececec`, карточки `#fff`, статусы — см. §2).

## 9. Открытые вопросы и проверки только на NAS

Вне герметичной цепочки; ручная валидация на реальном NAS перед релизом
(кандидаты в `test-on-nas-functional.sh`):

- Фактические теги SUI-виджетов (поля ввода, диалог, switch, radio) в DSM 7.3.2 —
  и фолбэк на нативные элементы, если виджет не экспонирован (§3).
- Видимость нового эндпоинта/вкладки `settings` и работа формы в реальном DSM.
- `SynoToken`/CSRF на `settings.cgi` в админ-сессии; недоступность для
  неаутентифицированных запросов.
- Запись конфигов со сбросом привилегий (`sudo -u sc-yandexdisk`) даёт файлы
  `sc-yandexdisk` с правильными правами; `rclone.conf` `0600` читается sync’ом.
- (Tier 2) реальный OAuth-redirect — **только после одобрения**.
- (Опция B) интервал/триггер расписания — **только после одобрения**.

**Решения, ожидающие человека (план §11):**
1. Объём подключения: оставить MVP Tier 1 или реализовывать Tier 2.
2. Расписание: оставить Опцию A (ручная задача) или вводить Опцию B (интервал).
