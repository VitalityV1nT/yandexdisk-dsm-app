### 1.2. Расхождения и пробелы (Д-1 … Д-7)

**Д-1 (дефект, блокирующий): эталонный тест Г-1 §4.3 внутренне противоречив.**
Сценарий «инкрементальный сбой с триггером ⇒ авто-recover ⇒ статус `idle`» запускается как
`FAKE_RC=1 FAKE_NEED_RESYNC=1 sh "$YD" sync`. Переменные окружения наследуются **всеми**
вызовами шима внутри одного запуска, поэтому восстановительный `_bisync --resync`
(`yandex-disk:179`) тоже получит `FAKE_RC=1` и завершится с ошибкой → обёртка запишет
`error|…|rc=1`, и assert «после авто-recover статус idle» гарантированно упадёт.
Кроме того, шим Г-1 печатает триггер `cannot find prior listing` и в resync-прогоне,
чего реальный rclone не делает. **Исправление — §2.1**: шим обязан различать
инкрементальный вызов и `--resync` (отдельные `FAKE_RC` / `FAKE_RESYNC_RC`; триггер —
только в инкрементальном вызове).

**Д-2 (пробел): push-CI не покрывает рабочие ветки.**
`build-spk.yml` триггерится на `push` только для `main`/`arm-support`
(`build-spk.yml:10`); текущая рабочая ветка `deterministic-1` получает гейт только после
открытия PR. До PR агент работает **без принудительного** CI — гейт держится на локальной
дисциплине. Исправление — W6.

**Д-3 (подтверждение §11.2 Г-1, с точными адресами): три «skip-дыры» в `build.sh`.**
`shellcheck` информационный и пропускается без установки (`build.sh:85–89`); JSON-проверка
пропускается без `python3` (`build.sh:91–95`); несовпадение ELF-архитектуры даёт `WARN`,
а не отказ (`build.sh:103–107`). Вердикт «зелёный build.sh» сейчас зависит от того, что
установлено на машине, — это скрытая недетерминированность. Исправление — W1.

**Д-4 (пробел): Г-1 требует создать `CLAUDE.md`, но не задаёт его содержимое.**
Точка входа агента — главный рычаг детерминизма процесса; её текст должен быть
зафиксирован как код. Канонический текст — §3; внедрение — W8.

**Д-5 (пробел): контекстные ловушки для агента в рабочем дереве.**
Локально (вне git, см. `.gitignore`) лежат двойники и артефакты, которые агент видит при
поиске по файлам и может по ошибке принять за рабочий код:
- `test_package/` — **устаревшая x86-копия** пакета с другим набором скриптов
  (`yandex-cleaner`, `last_status.cgi`); правка в ней — мёртвая правка;
- `spk/package/yandex-disk.x86_64.backup` — старая x86-обёртка;
- готовые `YandexDisk-ARM-*.spk` в корне и `downloads/` — сгенерированные артефакты.
Г-1 §11.6 говорит о «детерминизме контекста», но этих ловушек не называет. Исправление:
явный запрет в `CLAUDE.md` (§3, раздел «Периметр»).

**Д-6 (уточнение к §4 Г-1): герметичный тест `yandex-logger` требует стейджинга.**
`yandex-logger` и `start-stop-status` сорсят библиотеку по пути
`$YD_PKG_DIR/target/common.sh` (`yandex-logger:18–19`, `start-stop-status:11–12`), а в
дереве исходников она лежит в `spk/package/common.sh`. Для их герметичного запуска нужно
создать `$WORK/pkg/target` → symlink на `spk/package`. Обёртке `yandex-disk` это не
нужно — она сорсит `common.sh` из своего каталога (`yandex-disk:21–22`). Тест логгера —
опциональный T14 (§2.3): у логгера бесконечный цикл и ps-grep единственности
(`yandex-logger:22`), в CI он хрупок; приоритет ему не давать.

**Д-7 (дефект, найден и исправлен при верификации Г-2 2026-06-13): CRLF-дрейф
рабочего дерева.** `.gitattributes` принудительно держит LF для всех скриптов пакета,
**кроме** `spk/scripts/preupgrade` и `spk/scripts/postupgrade` (без расширения, поимённо
не перечислены). При `core.autocrlf=true` (этот WSL-чекаут) оба файла молча получали
CRLF: в git — LF, в рабочем дереве — CRLF, `dash -n` падал с невнятным «word unexpected
(expecting "do")», а собранный из такого дерева `.spk` унёс бы неисполняемые скрипты на
NAS. Это живой пример недетерминированности среды (Г-1 §11.1): один репозиторий —
зелёный CI и красный локальный гейт. **Исправлено**: оба файла добавлены в
`.gitattributes` (`text eol=lf`), рабочее дерево перевыкачано, `build.sh` зелёный.
Защита от рецидива — явный CRLF-гейт, пункт 7 в W1.

## 2. Исправленная герметика (замена Г-1 §4.2–4.3)

### 2.1. `test/fake-rclone` v2 (resync-aware)

Отличия от Г-1: (a) отдельные коды возврата для инкрементального и resync-вызова;
(b) триггер recovery печатается только в инкрементальном прогоне; (c) опциональный дамп
аргументов для контракт-теста CLI-флагов (T13).

```sh
#!/bin/sh
# test/fake-rclone — герметичный эмулятор rclone для off-NAS тестов.
# Управление через окружение:
#   FAKE_RC          — exit-код ИНКРЕМЕНТАЛЬНОГО bisync (без --resync); по умолчанию 0
#   FAKE_RESYNC_RC   — exit-код bisync --resync; по умолчанию 0
#   FAKE_SENT / FAKE_RECV / FAKE_MOD / FAKE_DEL — сколько маркеров дописать в --log-file
#   FAKE_NEED_RESYNC=1 — дописать триггер recovery (только в инкрементальном прогоне)
#   FAKE_ARGS_FILE   — если задан, сохранить туда аргументы bisync (по одному на строку)
set -u
case "${1:-}" in
  version) echo "rclone v1.74.2-fake"; exit 0 ;;
  bisync)
    log=""; prev=""; resync=0
    for a in "$@"; do
      [ "$prev" = "--log-file" ] && log="$a"
      [ "$a" = "--resync" ] && resync=1
      prev="$a"
    done
    [ -n "${FAKE_ARGS_FILE:-}" ] && printf '%s\n' "$@" > "$FAKE_ARGS_FILE"
    if [ -n "$log" ]; then
      emit() { i=0; while [ "$i" -lt "$2" ]; do printf '%s file%s\n' "$1" "$i" >>"$log"; i=$((i+1)); done; }
      emit 'Queue copy to Path2'        "${FAKE_SENT:-0}"
      emit 'Queue copy to Path1'        "${FAKE_RECV:-0}"
      emit 'Copied (replaced existing)' "${FAKE_MOD:-0}"
      emit 'Queue delete'               "${FAKE_DEL:-0}"
      if [ "$resync" -eq 0 ] && [ "${FAKE_NEED_RESYNC:-0}" = "1" ]; then
        echo "cannot find prior listing" >>"$log"
      fi
    fi
    if [ "$resync" -eq 1 ]; then exit "${FAKE_RESYNC_RC:-0}"; else exit "${FAKE_RC:-0}"; fi
    ;;
  config) exit 0 ;;
  *) exit 0 ;;
esac
```

## 5. Mutation-sanity: диверсии, которые гейты обязаны ловить

Прогоняется один раз при внедрении W2–W5 (и далее по Г-1 §11.4 — периодически).
Каждая диверсия вносится, гейт запускается, фиксируется **красный**, диверсия откатывается.

| # | Диверсия (временная правка) | Обязан упасть |
|---|---|---|
| 1 | В `count_run_transfers` заменить `Queue copy to Path2` → `…PathX` | `run-hermetic` T1 (`f4=0` вместо 2) |
| 2 | Убрать поле из `printf` в `write_sync_state` | `run-hermetic` T1/T12, golden (W7) |
| 3 | Вставить `[[ -n "$LOCAL" ]]` в `yandex-disk` | `dash -n` в `build.sh` (и checkbashisms после W1) |
| 4 | В `build.sh` заменить `--mtime` на текущее время | `check-reproducible` (W3) |
| 5 | Удалить `--exclude "@eaDir/**"` из `_bisync` | `run-hermetic` T13 |
| 6 | Подложить x86-бинарь вместо rclone | ELF-гейт `build.sh` (после W1 — exit 1) |

Гейт, не упавший на своей диверсии, считается неработающим: чинится гейт, а не таблица.
